The user requests one coded avatar and a picture rendered from exactly that code, before any further match development. Existing original WebGL2 meshes are the starting point. No paid/downloaded character pack, generative poster as evidence, or assertion of photorealistic likeness.

Build an isolated avatar HTML using the same renderer: one generic original male cricketer with denser sculpted face, integrated skin/beard coloration, fitted eyes/lids/brows, original hair and ears; original blue/gold cricket kit, bat and pads. Show full-body and portrait views, optional helmet, and front/side rotation. Original dimensions and paired bat grip remain shared with the game. Do not alter match behavior/scorer feed. Detail upgrade applies only to the study character until the user evaluates it.

Approach: extend the authored mesh/shader route and create an offline standalone study. A generated image cannot prove code output; a purchased scanned pack conflicts with the user's constraint. Realistic likeness and motion capture remain unfulfilled; this asset is an original analytic surface, not a scan.

Acceptance: finite outward mesh geometry, physical gear dimensions preserved, one avatar only in study, controls work, zero dependency network requests, actual WebGL2 portrait/full-body screenshots. Visual inspection decides what the tests cannot: face/eye fit, joint and equipment alignment, visibility.
